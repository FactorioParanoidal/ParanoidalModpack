# Работа с репозиторием с помощью GIT

### Клонирование проекта

Для клонирования проекта нужно иметь в системе установленный GIT и использовать команду

```shell
git clone https://github.com/FactorioParanoidal/ParanoidalModpack --depth 1
```

> **Note**  
> `--depth 1` нужен для того, что-бы не скачивать всю историю коммитов, которая, вероятно, вам не нужна.

> **Note**  
> `-b the-branch-i-ve-been-looking-for` если вам нужно склонировать определенную ветку

### Смена ветки

В случае, если вы клонировали репозиторий с `--depth 1`:

```shell
git remote set-branches origin '*'
git fetch -v --depth=1
```

И переключение ветки:
```shell
git checkout the-branch-i-ve-been-looking-for
```

### Обновление

В общем случае, когда вы не изменяли файлы локально:
```
git pull
```

Если изменяли и `git pull` выдает ошибку, откатитесь к состоянию ветки:
```shell
git reset --hard origin/master
```

> **Note**  
> `origin/master` вместо `master` должна быть другая ветка, если вы ее меняли

## Технические детали

### Окончания строк

Окончания строк важны не только для отображения diff. Factorio загружает содержимое модов как есть, а provenance
tooling считает хеш файлов. Поэтому один и тот же текстовый файл с `LF` на Linux и `CRLF` на Windows будет выглядеть
как два разных файла. Это приводит к ложным локальным изменениям, несовпадению хешей и потенциально разному
содержимому сборки.

По умолчанию Unix использует `LF`, а Windows часто использует `CRLF`. Если у пользователя включён
`core.autocrlf=true`, без явных правил Git может преобразовать окончания строк только в Windows checkout.

В репозитории для всех распознаваемых текстовых файлов принудительно задан `eol=lf` через `.gitattributes`. Это
правило имеет приоритет над пользовательским `core.autocrlf`, поэтому обычный `git clone` должен выдавать одинаковые
байты текстовых файлов на Windows и Linux. Бинарные форматы явно помечены как `binary` и никогда не проходят через
преобразование окончаний строк.

Проверить конкретный файл можно так:

```shell
git check-attr text eol -- mods/zzzparanoidal/info.json
```

Ожидаемый результат:

```text
mods/zzzparanoidal/info.json: text: auto
mods/zzzparanoidal/info.json: eol: lf
```

После изменения `.gitattributes` уже существующий checkout нужно нормализовать отдельно: новые правила применяются
автоматически к новым checkout, но не переписывают существующие рабочие файлы сами по себе. Не используйте
`git reset --hard`, если в рабочем дереве есть незакоммиченные изменения. Для подготовки нормализации:

```shell
git add --renormalize .
```

Проверьте diff, убедитесь, что меняются только окончания строк, и закоммитьте нормализацию отдельным коммитом. После
этого новые clone/checkout на Windows и Linux будут содержать одинаковые текстовые файлы.

`git add --renormalize .` обновляет представление файлов в индексе. Если в рабочем дереве уже есть функциональные
изменения, сначала внимательно проверьте diff и не смешивайте их с отдельным коммитом нормализации.
