# Проверка происхождения модов

Проверка `CheckModProvenance` запускается в CI для каждого PR и сравнивает локальные папки в `mods/` с `mods-metadata/!expected.json`.

Пользователю не нужно запускать отдельный скрипт или вручную пересчитывать хеши. Достаточно добавить или обновить мод и создать PR.

## Что проверяется

1. Все моды загружаются из текущей директории через `FactorioModpack.LoadFromDirectory`.
2. Для каждой папки локально считаются MD5 хеши файлов и итоговый `contentHash`.
3. Если в expected-файле есть та же версия и `contentHash`, мод считается неизменённым. Для документированного portal-патча также проверяется `metadataHash`.
4. Если папка отличается от expected-файла, обычная проверка завершается ошибкой. Mod Portal не вызывается, expected-файл не изменяется.

Для проверки обновлённых папок относительно Mod Portal используйте:

```shell
build.cmd CheckModProvenance --check-mod-portal
```

Команда скачивает точную версию из `info.json` и сравнивает содержимое. Если папка совпадает с upstream-релизом или отличие описано в metadata, проверка проходит, но expected-файл не изменяется.

В CI для PR из этого репозитория используется maintenance-режим (`--maintain-mod-provenance`): он может обновлять
`mods-metadata/!expected.json` и докоммичивать изменения в ветку PR. Для fork-PR запись не выполняется.
Чтобы принять проверенные состояния и записать новый expected-файл:

```shell
build.cmd CheckModProvenance --maintain-mod-provenance
```

Для локальной подготовки файлов metadata можно использовать:

```shell
build.cmd CheckModProvenance --prepare-mod-provenance
```

Prepare создаёт только отсутствующие файлы metadata для модов, у которых найден релиз Mod Portal, и не изменяет expected-файл. Причину изменения нужно заполнить вручную.

Maintenance удаляет metadata-файлы и expected entries для модов, которых больше нет в сборке. Expected-файл записывается только если каждое состояние является точной копией релиза Mod Portal, локальным project-модом или документированным изменением. При недокументированных правках, неизвестном источнике или сетевой ошибке файл не изменяется, а команда завершается ошибкой.

Если набор файлов и их содержимое совпадают, PR содержит чистую upstream-версию.

## Намеренные изменения

Если мод отличается от upstream намеренно, добавьте файл `mods-metadata/<mod>.json`:

```json
{
  "mod": "some-mod",
  "source": "portal",
  "upstreamVersion": "2.0.3",
  "changeReason": "Исправляет совместимость с Paranoidal"
}
```

Версия и причина обязательны: описание изменения, относящееся к старой версии, не переносится автоматически на обновлённый мод. Перечислять изменённые файлы не требуется, они выводятся в отчёте проверки.

Файл с `source: local` отключает сравнение для собственных модов проекта:

```json
{
  "mod": "zzzparanoidal",
  "source": "local",
  "changeReason": "Собственный мод проекта"
}
```

Для локального форка это же поле объясняет причину порта или изменения. Проверка не обращается к Git remote и не сравнивает ветки. Для PR из этого репозитория CI может запускать maintenance-режим и обновлять expected-файл; для forks остаётся read-only проверка.
