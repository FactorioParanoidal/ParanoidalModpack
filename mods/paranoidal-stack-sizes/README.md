# Paranoidal: Stack Sizes — единые размеры пачек

Служебный мод сборки Paranoidal для **Factorio 2.1.24**, основной ветки `pre_release_2.1`.
Он не добавляет предметов, рецептов, технологий или интерфейса. Его задача — сделать управление
размерами пачек предсказуемым: **один реестр правил, один итоговый проход**, вместо последовательных
перезаписей из Bob, Angels, BI, ReStack, энергетики, боеприпасов и точечных правок сборки.

## Где менять размер пачки

**Все настройки сборки находятся в [`config.lua`](config.lua).** Не добавляйте новые присваивания
`data.raw.…stack_size` в другие моды или в произвольный конец `data-final-fixes.lua`.

Разделы конфигурации:

| Раздел | Назначение |
|---|---|
| `initial` | Настраиваемые начальные пачки компонентов и покрытий Angels: по умолчанию берётся сохранённая startup-настройка; поле `size` позволяет задать явное значение здесь |
| `categories` | Категории ReStack: ресурсы, плавка, наука, здания, транспорт, топливо, боеприпасы, покрытия, тара. Ноль означает «это правило не меняет размер» |
| `pre` | Условия Bob/Angels, покрытия из startup-настройки, минимумы материалов, броня, ремонтные инструменты, служебные предметы Factorissimo |
| `bi` | Минимумы BI, условие 5Dim, ограничения и совместимость со Space Exploration |
| `early` | Прежние ранние исключения ядра и Marathon |
| `module_items` | Размеры всех 96 предметных прототипов импортируемого комплекта модулей Beta 8, включая маяки, инструменты и компоненты |
| `created_ammo` | Обязательные размеры десяти восстанавливаемых боеприпасов W93/Schall; их конструктор получает значения отсюда |
| `ammo` | Точные исключения боеприпасов после категорий |
| `energy` | Пачки четырёх видов топлива; их топливные свойства сюда не перенесены |
| `inherited_defaults` | Явные связи поздних копий с уже настроенным родителем: две тяжёлые брони и электролизёр MK3; без дублирования чисел |
| `exceptions` | Явно согласованные точечные значения, в том числе правка 15 предметов от 2026-11-10 |
| `empty_barrels` | Идентичность пустой тары для совместной обработки пачек и разливки |

Обычно для нового точечного решения достаточно добавить предмет в `exceptions`. Например,
`{source = "approved-change", size = 50, names = {"item-id"}}`.
По умолчанию это тип `item`; для боеприпаса, инструмента или брони укажите `kind = "ammo"`,
`"tool"`, `"repair-tool"` или `"armor"`. Внутреннее имя и тип должны существовать в итоговой сборке.
Исключение не должно нарушать флаг `not-stackable`: такой предмет обязан иметь размер 1.

## Что означает «одно место»

Исходные объявления предметов в их модах сохраняют обязательное поле `stack_size`.
Это **базовое определение прототипа**, а не дополнительная настройка баланса сборки.
Настраиваемые начальные размеры компонентов и покрытий Angels получают значение через `config.initial_size`,
так что выбор их источника также находится здесь, а прежние ID и сохранённые startup-настройки поддерживаются.
Если предмет не попал ни под одно правило, он сохраняет объявленный размер; в аудите его источник — `declared`.
Поэтому поиск слова `stack_size` по всему модпаку по-прежнему находит много корректных определений
и чтений значений. Их нельзя массово удалять или принимать за конкурирующие переопределения.

Отдельный случай — импорт модулей Beta 8: числовые размеры удалены из его сериализованного снимка.
Загрузчик `zzzparanoidal/prototypes/modules-beta8.lua` получает обязательные начальные значения
из `config.module_items` до регистрации новых прототипов. Аналогично, конструктор десяти восстанавливаемых
боеприпасов получает размеры из `config.created_ammo`. Локальных вторых списков размеров у них нет.

## Состав и порядок работы

Тесты из таблицы ниже хранятся вне игровой поставки: `D:/PARANOIDAL/test-runs/mod-tests/paranoidal-stack-sizes/tests/`. Для их прежней раскладки используется отдельная копия, собранная через `D:/PARANOIDAL/tools/mod-development/prepare.py` с обоими модами `paranoidal-stack-sizes` и `zzzparanoidal`.

| Файл | Роль |
|---|---|
| `config.lua` | Единственный реестр числовых правил и списков исключений |
| `selection.lua` | Снимок принадлежности предметов категориям в исторической точке ReStack; не изменяет прототипы |
| `requests.lua` | Накопление вычисляемых ограничений генераторов, без изменения прототипов |
| `rules.lua` | Разрешение приоритетов в виртуальном плане и единственное применение к существующим предметам |
| `data-final-fixes.lua` | Запуск итогового прохода и публикация аудита |
| `info.json` | Явный порядок после модов, имеющих финальную стадию; это не надежда на алфавитное имя |
| `tests/rules.lua` | Изолированные проверки приоритетов, единственной записи, типов/флагов, настроек, вычисляемых минимумов и наследования |
| `changelog.txt` | История изменений компонента |

`zzzparanoidal` вызывает `selection.capture(data.raw)` ровно там, где раньше выполнялся ReStack:
после ранних замен и до поздней переработки рецептов/прототипов. Это важно: перенос самого поиска
категорий в конец загрузки мог бы включить другие рецепты и незаметно изменить размеры.
Снимок хранит только выбор категорий, тары и прежних продуктов запуска, а не копию полного дампа.
Алгоритм категорий происходит из уже включённого в сборку порта ReStack (Optera).

После этого обычные моды завершают создание прототипов. Зависимости этого служебного мода
обеспечивают его финальный проход после существующих `data-final-fixes.lua`, включая IC и BnL.
Внутри прохода правила последовательно разрешаются **в отдельном плане**, а не записываются
одно за другим в `data.raw`. К каждому итоговому предметному прототипу производится не более одной
записи; если значение уже верно, записи вообще нет.

Порядок приоритетов: исходное объявление → совместимость `pre` и вычисляемые минимумы → BI →
ранние правила ядра/Marathon → тара и категории исторического ReStack → комплект модулей →
точные боеприпасы → топливо → наследуемые размеры поздних копий → согласованные исключения.

## Вычисляемые ограничения и совместимость

- WideChests регистрирует минимальную пачку исходного сундука по **реальной максимальной площади**
  сгенерированных объединённых сундуков. Он не меняет пачку немедленно. Число ячеек сундуков не затронуто.
- `angelsmods.functions.override_item_conditions` сохранена как совместимый API для внешних интеграций:
  она регистрирует минимум через `requests.minimum`, а не перезаписывает прототип. Известные настройки
  самой сборки перенесены из её старых вызовов в `config.lua`.
- BI сохраняет условные ветки для Space Exploration и 5Dim. Отсутствующие необязательные предметы
  безопасно пропускаются; это не разрешение удалять эти интеграции из кода.
- Размеры обычных предметов и специальные свойства инвентарей различаются. Например, служебный
  сундук Factorissimo с `stack_size_multiplier = 50` остаётся в Factorissimo.
- Бонусы горсти манипуляторов, число слотов сундуков/вагонов и масштабирование их слотов качеством
  не являются `ItemPrototype.stack_size` и этим модом не перенастраиваются.

Обработка вместимости бочек, партий наполнения/опорожнения, времени и топливной ценности остаётся
в `zzzparanoidal/tweaks/custom/barrel-port.lua`. Старый файл ReStack удалён, а не оставлен вторым
переопределителем. Нельзя отключать обработку разливки под видом удаления правок пачек.

## Аудит и сопровождение

В итоговом `data.raw["mod-data"]["paranoidal-stack-sizes-audit"].data` доступны:

- `count`: число охваченных предметных прототипов всех предметных типов;
- `changed`: число фактических итоговых изменений в единственном проходе;
- `sources`: распределение по окончательно выбранному правилу;
- `items["type/name"]`: итоговый `stack_size` и `source` для каждого предмета.

Журнал содержит строку `Stack sizes: … item prototypes, … changed in one final pass`.
Аудит объясняет выбор правил, но сам по себе не доказывает сохранение баланса: для этого сравниваются
полные итоговые прототипы до/после изменения. Новые предметы не считаются автоматически ошибкой,
но требуют явного решения об их размере/категории.

### Agent maintenance contract

- Keep all build tuning in `config.lua`; keep algorithms free of balance constants.
- Preserve the category capture boundary. Do not turn the snapshot into a later rescan of changed recipes.
- Register generator-derived constraints through `requests.minimum`; do not patch item prototypes from generators.
- When adding/updating a mod with final-stage prototype creation, extend the optional dependencies in
  `info.json` (or prove an existing transitive dependency). Never introduce a dependency cycle.
- Keep this service enabled together with the adapted full modpack. It is not an independently optional
  gameplay feature; upstream-style standalone use of the adapted foreign mods is not this build's target.
- Preserve Space Age / Space Exploration groundwork, existing setting IDs, prototype IDs and quality support.
- Use the workspace's isolated Factorio 2.1 runner. Compare every item type/name/stack size and all other
  prototype fields against the same-input baseline. Verify the new mod actually loaded and finalized last.
- Check syntax and targeted pure-rule cases first. A dump does not verify control-stage behavior or saves.
- Do not add migrations for this organizational move when final sizes are unchanged. A future reduction
  of sizes needs a separate save-impact assessment; do not truncate inventories by script.
- Update this README and the current changelog section when the ownership or precedence model changes.

## Установка и сохранения

Мод включён в рабочем `mod-list.json` с разрешения пользователя. Сам этот файл, настройки `.dat`
и сохранения не входят в Git. После установки нужен обычный перезапуск игры, чтобы загрузить мод.
Данные инвентарей скриптами не переписываются. При первоначальном переносе цель — сохранить все
итоговые размеры исходной сборки, включая последние 15 согласованных значений, без миграции предметов.
Новый служебный мод вызывает штатное изменение конфигурации модов; неизменность размеров не является
доказательством исправности посторонних `on_load`/`on_configuration_changed` обработчиков модпака.
