# Paranoidal Deep Storage (Хранилища материопамяти)

Мод сборки [Paranoidal](https://github.com/FactorioParanoidal/ParanoidalModpack). Объединяет локальные форки двух модов **notnotmelon** — [Memory Storage](https://mods.factorio.com/mod/deep-storage-unit) 1.6.8 (`deep-storage-unit` 9.8.0) и [Fluid Memory Storage](https://mods.factorio.com/mod/fluid-memory-storage) 1.7.9 (`fluid-memory-storage` 9.8.0) — и логистические хранилища по [Logistic Memory Units](https://mods.factorio.com/mod/logistic-memory-unit) (restjack, MIT). Спасибо авторам. Происхождение для проверок сборки: `mods-metadata/paranoidal-deep-storage.json`.

Имена прототипов, технологий, рецептов, настройки и ключей локали прежние: правки сборки (`zzzparanoidal/final-fixes/recipies.lua`, исключения брака в `ic-more-qualities`, достижения MxlChievements, логистическое меню) работают без изменений. Русские тексты для игры — `ParanoidalLocale/locale/ru/paranoidal-deep-storage.locale.cfg` (перекрывает `locale/ru` мода).

## Хранилище материопамяти (предметы)

Сундук 6×6 на 300 слотов, привязанный к одному предмету одного качества.

- Раз в секунду в сундуке остаётся 150 стопок (буфер для манипуляторов), остальное уходит в счётчик материопамяти; при нехватке буфер пополняется из счётчика. Количество не ограничено.
- Блок привязывается к первому предмету в пустом сундуке или к предмету в руке (кнопка в окне). Пустой блок отвязывается кнопкой «Сбросить».
- Не принимаются портящиеся предметы и предметы с содержимым или данными (броня и всё с сеткой оборудования, техника, предметы с тегами и инвентарём, чертежи и планировщики). Блок, уже привязанный к такому предмету в старом сохранении, работает в режиме «Только выдача».
- Логистические варианты (пассивное снабжение 90 %, хранение 10 %, буферный 50 %, запрос 25 % сундука): сундук видит логистическая сеть, счётчик стоит за ним. Хранение ставит фильтр хранения на хранимый предмет; фильтр на пустом блоке привязывает его. Активного снабжения нет.
- В Alt-режиме видны иконка предмета (и качества) и количество.

## Ёмкость материопамяти (жидкости)

Резервуар 3×3 на 120 000, привязанный к одной жидкости.

- Раз в секунду в резервуаре остаётся половина его объёма, остальное — в счётчике.
- Привязка к первой жидкости в резервуаре или к жидкости, выбранной заранее в окне; пустая ёмкость отвязывается кнопкой «Сбросить».
- Температура одна на всё хранимое: при смешивании остаётся меньшая (решение пользователя 2026-10-14); из счётчика жидкость возвращается с этой температурой.

## Общее

- Скрытый комбинатор передаёт в логическую сеть общее количество (не больше 2,1 млрд).
- Энергия: `(1 МВт + ceil(количество / размер стопки) ^ 0,35 × множитель) × коэффициент качества`; для жидкостей стопка — 1000. Множитель — настройка карты «Энергопотребление материопамяти», в сборке 480 кВт. Коэффициент качества `0,2 + 0,8 × (1 − i/N)²` по цепочке качеств игры; брак и скрытые качества скидки не дают. При питании меньше 90 % ничего не переносится.
- При разборке содержимое сохраняется в упакованном блоке (предмет с тегами). **При разрушении всё содержимое теряется.** Призрак упакованного хранилища не несёт содержимое.
- Переименования предметов, жидкостей и качеств из миграций запоминаются и применяются к стоящим и упакованным блокам; удалённый предмет оставляет блок пустым с сообщением в чат.

## Устройство скрипта (9.0.0)

- `storage.units` — хранилища предметов, `storage.fluid_units` — ёмкости. Один планировщик: `on_nth_tick(15)`, 4 слота, каждый блок раз в секунду; блоки разложены по слотам заранее и пересобираются только при изменении набора блоков.
- Окна обновляются раз в 2 тика только пока хоть одно открыто (`storage.open_guis`, обработчик подписывается и снимается по ходу игры и восстанавливается в `on_load`).
- Источник питания записывается только при смене потребления (число хранимых стопок), его буфер не читается обратно; настройка мощности читается один раз, коэффициент качества блока кэшируется. Надпись Alt-режима переписывается только при смене округлённого числа.
- Скрытые части, уже стоящие на месте блока, подхватываются, а не создаются вторыми — провода комбинатора сохраняются.

## Старые сохранения

- `deep-storage-unit` 9.9.0 — мост переноса: Factorio хранит `storage` под именем мода, поэтому содержимое хранилищ предметов из старых сохранений лежит в нём. При первой загрузке старого сохранения этот мод (в `on_configuration_changed`) находит все блоки на всех поверхностях, забирает у моста предмет, качество и количество каждого хранилища через `remote` `deep-storage-unit-migration` и подхватывает скрытые части. Мост держать включённым, пока загружаются такие сохранения.
- Ёмкости жидкостей переходят **без счётчика** (согласованная потеря): жидкость, хранившаяся вне резервуара, пропадает; жидкость в самом резервуаре остаётся, и ёмкость снова к ней привязывается.
- История изменений форков — в Git (`mods/deep-storage-unit`, `mods/fluid-memory-storage`) и в `changelog.txt` моста.
