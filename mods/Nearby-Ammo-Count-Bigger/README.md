# Nearby Ammo Count (Paranoidal bigger text)

Локальный форк мода [Nearby Ammo Count](https://mods.factorio.com/mod/Nearby-Ammo-Count) (автор — Schmendrick / Loren1350) для сборки Paranoidal, Factorio 2.0. В alt-режиме над турелями с патронами (`ammo-turret`) рядом с игроком показывается запас боеприпасов. Жидкостные турели, артиллерия и вагоны не поддерживаются.

Отличия форка от исходного мода:

- текст увеличен в 2,5 раза, чтобы читаться при обычном масштабе;
- скрипт переписан ради производительности (октябрь 2026, см. ниже);
- добавлен показ только турелей с нехваткой боеприпасов.

## Настройки

| Настройка | Тип | По умолчанию | Что делает |
|---|---|---|---|
| Частота обновлений | карта | 4 раза/с (1, 4, 10, 20) | Сколько раз в секунду обновляется каждая турель. Работа распределяется по тикам равномерно |
| Режим отображения | карта | Количество магазинов | Выстрелы, магазины, значок или значок, растущий с нехваткой |
| Цвета: нормальный / малый / критический запас | карта | зелёный / жёлтый / красный (два последних скрыты) | Прозрачность 0 скрывает уровень полностью: объекты для него не создаются |
| Показывать только нехватку боеприпасов | игрок | включено | Скрывает числа над турелями, которые манипуляторы уже заполнили |
| Порог нехватки, % | игрок | 100 (1–100) | Число видно, пока магазинов в турели меньше `automated_ammo_count × %` |

Уровни в текстовых режимах: не больше 1 магазина — критический, меньше `automated_ammo_count` — малый, иначе нормальный. `automated_ammo_count` — лимит из прототипа турели: манипулятор докладывает боеприпасы, пока их меньше этого числа. Поэтому при пороге 100% число видно ровно до момента, когда манипулятор перестаёт докладывать. При меньшем пороге видны только турели с более глубокой нехваткой.

**Пустая турель показывается всегда** при любом пороге: «0» в критическом цвете, в режимах со значком — значок максимальной тревоги. Исключение — текстовые режимы с критическим цветом, у которого прозрачность 0.

Значки в режимах «Значок» видны без alt-режима, числа — только в alt-режиме (как в исходном моде).

## Как работает

- Каждый подключённый игрок раз в 30 тиков проверяется на необходимость нового поиска. Турели в радиусе 100 клеток ищутся заново, если игрок сдвинулся на 16 клеток, сменил поверхность или силу, изменились союзы сил или прошло 300 тиков с прошлого поиска. Ищутся только турели своей силы и сил, которые считают её другом.
- Турели, построенные рядом с игроком (игроком, роботом, скриптом, клонированием), добавляются сразу по событиям постройки.
- Отслеживаемые турели хранятся в `storage` по `unit_number`; турель рядом с несколькими игроками учитывается один раз.
- Каждый тик обрабатывается `ceil(N / период)` турелей по кругу, так что каждая обновляется один раз за период.
- На турель — не больше одного постоянного объекта `rendering`, видимого только нужным игрокам (`players`). Текст, цвет, масштаб и список игроков меняются только при реальном изменении. Если показывать никому не нужно, объекта нет.
- Изменение глобальной настройки мода пересоздаёт объекты, изменение настройки игрока — только его порог. Настройки других модов игнорируются.
- `on_configuration_changed` сбрасывает состояние; старые сейвы без состояния инициализируются в первом тике. Миграции не нужны.

## Исправленные проблемы (2.0.1, октябрь 2026)

### Производительность

| Было | Чем грозило | Стало |
|---|---|---|
| Каждое обновление создавало новый текст или значок для каждой турели рядом с игроком со временем жизни ровно в один период | При 300 турелях и 4 обновлениях в секунду — около 1200 созданий и удалений объектов `rendering` в секунду, даже если числа не менялись | Постоянный объект на турель, обновляется на месте только при изменении |
| Все турели обрабатывались в одном тике по `on_nth_tick` | Пик нагрузки раз в период: при 1 обновлении в секунду — рывок раз в секунду, при 20 — каждые 3 тика | Обработка порциями по кругу на каждом тике |
| `find_entities_filtered` в радиусе 100 вокруг каждого игрока на каждом обновлении, включая вражеские турели | До 8×8 чанков на игрока 4–20 раз в секунду, даже стоя на месте | Поиск только при движении, смене поверхности или силы, смене союзов и раз в 5 секунд; только дружественные силы; новые турели — по событиям |
| Полные турели всё равно получали объект (скрыть можно было только прозрачностью 0) | Основная часть работы уходила на числа, которые не нужны | Полные турели и уровни с прозрачностью 0 вообще не создают объектов |
| Турели собирались в таблицу с ключом-объектом `LuaEntity` | Объекты `LuaEntity` от разных вызовов — разные ключи, поэтому турель рядом с двумя игроками рисовалась дважды | Учёт по `unit_number`, один объект с несколькими зрителями |
| Любое изменение любой runtime-настройки любого мода перечитывало все настройки и перерегистрировало `on_nth_tick` | Лишняя работа, в том числе при per-user настройках других игроков | Обрабатываются только настройки `nearby-ammo-*` |

### Ошибки

- **Значки видели все силы, включая врагов:** при отрисовке значков не задавался параметр `forces`. Теперь объекты видят только игроки своей и дружественных сил, находящиеся рядом.
- **Числа над турелями сил, созданных после загрузки, видели все:** таблица союзов строилась при загрузке и не обновлялась при `on_force_created`. Теперь силы проверяются при каждом поиске.
- **Значки рисовались под эстакадными рельсами:** слой `139` из Factorio 1.1 в 2.0 относится к слоям эстакады. Теперь используется слой `entity-info-icon-above`.
- **Мерцание и двойная отрисовка:** время жизни объекта равнялось периоду обновления, поэтому текст мог пропадать на кадр или на мгновение рисоваться дважды. Постоянные объекты убрали проблему.
- **Пустые турели не показывались ни в одном режиме**, хотя это самая опасная ситуация. Теперь показываются всегда.
- Удалены глобальная переменная `l`, утёкшая из `team_views`, параметр `target_offset` (в 2.0 его нет, положение текста не изменилось) и неиспользуемый код (`drawparams`, `initialize`, `color_*`).

## Проверки

- `luac -p` для `control.lua`, `settings.lua`, `data.lua`.
- Mock-тест логики вне игры (51 проверка): пороги, пустые, переполненные и чужие турели, отсутствие записей без изменений, два игрока с разными настройками, уход игрока, удаление от турелей и периодический поиск, постройка и уничтожение турелей, союз сил, все четыре режима, распределение по тикам, сброс и старый сейв. Тест ловит три намеренно внесённые ошибки.
- Создание карты в изолированном профиле полного модсета (Factorio 2.0.77, Quality и Elevated Rails, без Space Age): exit 0, ошибок и предупреждений по моду в логе нет.

Не проверены в игре: показ над реальными турелями, работа с манипуляторами, режимы значков и UPS на большом периметре.

## Возможные доработки

- Если другой мод вызовет `rendering.clear()` без имени мода, числа над неизменными турелями вернутся только после изменения их запаса или настроек. В сборке таких вызовов нет.
- Для турелей с несколькими слотами лимит `automated_ammo_count` считается общим на все слоты; это стоит подтвердить в игре.
