Version: 9.0.0
Date: 2026.10.25
  Info:
    - Renamed to robotarmy-reforged (title Robot Army Reforged); incompatible with the original robotarmy mod (same prototype names).
    - Paranoidal fork. The control script is rewritten; save compatibility with 2.4.x is not kept (a save with 2.4.x data starts the mod state over and picks up the droids and buildings found on the map).
  Balancing:
    - The droid technology tree starts in the chemical science era and uses military science packs throughout: Army robotics (after chemical science pack, military 3, automation 3, circuit network) -> Riflebot -> Battle droid -> Rocket droid / Flamebot -> Terminator (with utility science, after military 4, power armour and laser turrets 2); Army robotics -> Defender -> Distractor -> Destroyer robot units (after the matching Bob's robot technologies). A technology also asks for the science packs of its prerequisites from other mods.
    - Recipes are rebuilt from Bob's, Angels and Paranoidal parts and cost about five times more: weapon, frame or armour (invar, cobalt steel, titanium, modular or power armour), actuators (bearings, gears, electric engines), power and control (circuits, batteries, processing units). Flying units are built from ten Bob's combat robots of their type and five combat brains of the same tier. Without these mods every ingredient falls back to a vanilla item.
    - The droid assembler and the guard station are built from an assembling machine 3 and intermediate structure components.
    - Droid recipes take about twice as long to craft.
  Optimizations:
    - The squad integrity check no longer reads the unit group member list once per member (was O(n^2) API calls per check); membership is read from each droid's parent group.
    - script.active_mods is no longer read every tick for every force and on every squad update (each read built a table of all active mods).
    - on_entity_died uses event filters (force and unit types) instead of handling every death in the game; QRF settings are cached.
    - Built events use name filters; destroyed droids and buildings are removed through on_object_destroyed instead of growing tables (storage.units was never cleaned before).
    - Droid assemblers and guard stations are checked round robin, evenly spread over the ticks; one count_entities_filtered call with all droid names instead of eight.
    - Droid counters are written only when a count changes, with one assignment of the section filters (each set_slot/clear_slot raised an event for every listening mod every second); only forces that use the mod are processed.
    - No per-tick work for forces without droids or buildings; retreat merging runs from the squad update instead of scanning every assembler every tick.
    - Hunting squads that find no enemy search less often (up to every 30 s) until they find one.
    - Proximity searches use the cached squad position before reading the unit group position.
    - The always-on logger (an endlessly growing script-output/logs/robotarmy file) and the session statistics are removed; an optional debug setting writes to factorio-current.log.
  Bugfixes:
    - Adding the mod to a save no longer runs force.reset_recipes()/reset_technologies() for every force (it disabled recipes unlocked by scripts of other mods); the old migrations are removed.
    - Deployed droids keep the quality of the droid item, and quality modules in the droid assembler can no longer raise it (deploy recipes have no product); picked up droids return as items of their quality and health; refused duplicate buildings are returned with their quality.
    - Guard stations spawn on their own surface (surface 1 was hard-coded).
    - QRF ignores squads on other surfaces, does not overwrite the saved state of a squad that is already responding, and does not command squads while Unit Control is active.
    - Retreating squads only consider assemblers on their own surface.
    - Spawn positions are searched for the droid's collision box instead of the building's.
    - Guard garrisons get an order to stay at their station and are sent back when they wander off more than 15 tiles; failure handling keeps them in guard mode.
    - Droids created by other mods (script_raised_built/revive, cloning) join squads.
    - Selection and pick-up use the surface of the selection (map view on another surface).
    - The tool hotkey works (the old hotkeys had action = "lua" without a handler).
    - A droid kicked out of its squad is no longer left without a squad when there is no assembler.
    - Counters and guard stations are removed from the tables when destroyed.
  Changes:
    - Deploying without placeholder items: a deploy recipe consumes the droid item in a droid assembler or guard station and every finished craft becomes a droid. When there is no room (too many droids around the assembler, full garrison) the finished droids wait and the machine pauses; a removed machine drops its waiting droids as items. The eight "deployable" items are removed.
    - One squad command tool instead of two: drag over a squad to pick it, Shift + drag to send it (attack-move), right-drag to pick droids up. One shortcut and one hotkey.
    - Army window (shortcut "Droid army" or its hotkey): squad thresholds of the force (hunt from, retreat at, hunt radius) with sliders, and the list of squads with composition, state and actions: show on the map, pick, recall or release.
    - Recalled squads go back to the nearest droid assembler and wait there until they are released or sent with the tool.
    - Panel next to the droid assembler and guard station window: droids waiting to be deployed; the guard station sets its own garrison size (copy-paste between stations copies it).
    - The droid settings module and its four signals are removed; their settings are in the army window and the guard station panel.
    - A picked squad shows only to the picking player: a mark on every member, a label with the squad number and size, and a line to where it is going (instead of a slowing sticker entity).
    - Alerts with a map marker instead of chat messages for responding squads (removed when the last one is back), squads without an assembler and stuck squads; the lost squad message has a map link. Flying text instead of chat for the tool.
    - Hunting squads that become too small retreat on their next update; finished orders of a squad are followed by a new order on its next update.
    - Droid assembler: 3 module slots (the 1.1 module_specification was ignored by 2.0, so it had none).
    - Map settings: QRF for vehicles, QRF for walls, QRF alert, targeting mode (nearest / defend assembler / keep radius clear; the last two were only reachable by editing the code), teleporting stray droids, squad alerts, debug log.
    - Startup settings: army loot chest (off; the chest, its recipe and unlock exist only when on), harmless acid puddles (off; the original always removed the damage of every acid splash fire), droid health and damage multipliers.
    - Remote interface "robotarmy-reforged": squads, thresholds, set_threshold, spawner, set_garrison, tracked_units, squad_of.
  Graphics:
    - Droid counter activity LED uses the 2.0 sprite size; the loot chest has a 2.0 circuit connector.
    - Symmetric selection boxes of the ground droids.
    - Deploy recipes show the droid icon.
  Locale:
    - Messages are localised (en, ru); descriptions match the current behaviour. Russian names reworked (Заводной стрелок for the Clockwork Riflebot, звено роботов for the flying units).
  Modding:
    - Code split into lib/shared.lua, prototypes/*.lua and script/*.lua; no globals are written in any stage. Recipes and technologies are created in data-updates so that the items and technologies of Bob's, Angels and Paranoidal exist; optional dependencies on bobwarfare, bobplates, angelssmelting and zzzparanoidal set the load order.
    - Removed the unused stdlib, 30log, robolib, config, migrations, WARP.md, QRF_Testing_Commands.txt, .gitignore, unused images (low resolution sprites, patrol pole, settings module, deployable item icons, settings signals, pick-up tool), and prototype fields that 2.0 does not read (destroy_action, idle, icon_mipmaps, is_deployer, item_slot_count, base_area/base_level, stackable, hr_version, ammo_type category).
    - ai_settings use the 2.0 field destroy_when_commands_fail.

Version: 2.4.27
Date: 2025.10.06
  Major Features:
    - Added Quick Reaction Force (QRF) system - squads automatically respond to building destruction within configurable range
    - QRF squads attack threat area, then return to their original positions and resume previous behavior
    - New runtime setting "QRF Response Distance" (0-500 tiles, default 500) - adjustable in-game without restart
  Settings:
    - Fixed mod loading error caused by incorrectly placed int-setting in data phase
    - Moved QRF distance setting to proper settings.lua file with full localization support
    - Added mod setting descriptions in English locale
  Stability:
    - Added comprehensive crash protection for pick-up tool interactions during QRF operations
    - Implemented protected API calls (pcall) for all unit group operations to prevent invalid commandable errors
    - Added squad member count validation to prevent operations on empty squads
    - Enhanced error handling with graceful QRF state cleanup when squads become invalid
  Quality of Life:
    - Added detailed QRF debug messages for testing and troubleshooting
    - Created comprehensive testing command file (QRF_Testing_Commands.txt) with console commands
    - Improved QRF state management with proper cleanup in all edge cases
