# Изменения Paranoidal в Merging Chests (WideChests) 6.2.4

Локальный portal-патч (`mods-metadata/WideChests.json`). Версия мода не менялась, имена прототипов те же, миграции не нужны. При обновлении с портала правки нужно перенести или проверить, исправлены ли ошибки upstream. Версия 6.3.0 предназначена для Factorio 2.1, судя по её changelog, эти ошибки в ней не исправлены.

## Исправленные ошибки

| Где | Было | Стало |
|---|---|---|
| `control_init.lua`, `can_move_inventories` | Размер объединённого сундука из прототипа ещё раз умножался на число клеток и множитель, а лимит брался из настроек по имени объединённого сундука. При множителе ≠ 1 проверка пропускала больше стопок, чем помещается, лишние удалялись без предупреждения. При настройках Paranoidal (0.3, лимит 220) 2×2 терял до 11 стопок, 2×4 — до 105. Сундуки из 2–3 клеток, наоборот, отклонялись без причины | Вместимость объединённого сундука — размер его прототипа с учётом качества |
| `control_init.lua`, `move_inventories` | Сундук без инвентаря в списке целей молча пропускал предметы | Такие цели пропускаются, предметы идут в следующий сундук |
| `control_init.lua`, `get_total_bar`; `merge_chest.lua`, `split_chest.lua` | Сундук без планки считался ограниченным полным размером. После разделения 2×2 без планки получались 4 сундука с планкой примерно на 15 слотах. Планка передавалась через `create_entity`, где нумерация отличается от `get_bar` | `nil` — планки нет. Если планки нет ни у одного исходного сундука, её нет и у результата. Доступные слоты распределяются по сундукам в порядке заполнения (например 10 → 10/0/0/0), сундук с полным числом слотов остаётся без планки. Для построенных сундуков — `LuaInventory.set_bar` с той же нумерацией, что `get_bar`. Для призраков — по-прежнему через `create_entity` |
| `control_init.lua`, `reconnect_circuits` | `ipairs` по словарю `get_wire_connectors` (ключ — `wire_connector_id`): если у сундука был только зелёный разъём, провод не переносился. Происхождение провода (script/radars) терялось | `pairs`, происхождение передаётся в `connect_to`. Связи внутри результата строятся только между существующими сундуками |
| `split_chest.lua` | Если один из сундуков не создавался, обработка проводов падала на `nil` | Созданные сундуки удаляются, объединённый остаётся без изменений |
| `merge_chest.lua`, `split_chest.lua` | Поверхность и сила брались у игрока | Берутся у исходных сундуков |
| `rotate_blueprint.lua` | Вызов `get_blueprint_entities` на вложенной книге (в 2.0 книги могут быть вложенными). Записи из библиотеки игнорировались. Не поворачивались `pickup_position`/`drop_position` (bobinserters), `orientation` транспорта и сетка привязки. Глобальная переменная `player`. Разрешённость поворота проверялась по настройкам размера, а не по наличию прототипа | Спуск по активным индексам вложенных книг. Записи — только если `valid_for_write`. Векторы, ориентация и сетка поворачиваются. Проверяется наличие прототипа повёрнутого сундука |
| `data_init.lua`, `create_entity` | У объединённых сундуков не было сопротивлений, `impact_category` и искр при повреждении. Обломки и взрыв — общие `medium-*`. Устаревшее `vehicle_impact_sound` | Копируются сопротивления, `impact_category`, `damaged_trigger_effect`, обломки и взрыв исходного сундука (если не заданы — прежние `medium-*`). `vehicle_impact_sound` убрано |

## Не менялось

Время разборки 2 с, применение инструмента без ограничения дальности, временный чертёж на каждый призрак при чтении планки, глобальные `math.round/gcd/lcm` и `prng` на этапе данных.

## Не проверено в игре

Нумерация `bar` в `create_entity` для призраков. Поворот сетки абсолютной привязки. Внешний вид обломков стального сундука на больших складах. Записи библиотеки «Мои чертежи», которые API помечает как недоступные для записи.
