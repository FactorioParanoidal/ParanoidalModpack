  Features:
    - Added PlanetsLib.assign_entity_removal_floor(planet, entities, default_tile, options). When configured simple entities are marked for deconstruction over tiles that destroy dropped items, PlanetsLib places temporary tile ghosts under them, pauses deconstruction until the floor is built, and then resumes it. Robot-built temporary floors are removed after the entity's drops are collected. Rules are stored per planet and entity in the Planetslib mod-data prototype's entity_removal_floors table, and each rule has its own default tile.

Version: 2.3.0
Date: 2026-10-21
  Features:
  Changes:
    - Ground diggers are no longer generated for mining drills that can only mine specific resource sites, such as pumpjacks or anomaly collectors. Such drills must be able to mine ordinary solid resources (their resource_categories must include basic-solid, or be unset).
  Bugfixes:
    - PlanetsLib.crushing_recipe_icons() and PlanetsLib.asteroid_crushing_recipe_icons() now use their icon_size argument instead of always declaring the supplied icon as 64 pixels. The icon keeps its previous apparent size, so existing icons look unchanged.
    - PlanetsLib-disable-all-entity-replacements now actually disables all entity replacement rules at runtime, including rules bound to their own startup setting and migrations.
    - Entity replacement migration now reverts rules that were removed between saves, handles belt-like entities (transport belts, underground belts, splitters and loaders) via the engine's fast-replace path, and no longer tries to replace entities while the global entity-replacement setting is disabled.
    - Ground diggers now respect the per-planet drill blacklist when assigning the locked recipe, and placement collision checks use the prototype selection box (the actual footprint) instead of tile_width/tile_height (the placement grid). This covers the full footprint, ignores adjacent entities outside it, and rejects colliding real entities and entity ghosts inside it. Ghost collisions no longer show the custom entity-in-the-way label, allowing the vanilla build overlay to remain visible. Directly placing a ground digger over its own ghost now builds the matching ghost closest to the cursor, while other entity ghosts still block placement.
    - The backwards-compatibility tier helpers now return nil when the separate PlanetsLib: Tiers mod is not installed instead of erroring.
    - rro.amend() is now the canonical in-place table merge and returns the mutated table for convenience. The misspelled rro.ammend() remains as an alias for backwards compatibility.
    - get_planet_str_double() now truncates long planet names in its fallback, matching get_planet_str().
    - Removed a leftover entity-replacement debug print that wrote to the log for every replacement.

Version: 2.2.2
Date: 2026-10-20
  Bugfixes:
    - Restored the documented PlanetsLib.restrict_to_surface() export in the public API.
    - Absolute positions calculated from nested orbits now use the same polar convention as the other orbit helpers, so orbit positions are no longer rotated 90 degrees relative to the rest of the library.
    - PlanetsLib.assign_rocket_part_recipe() now accepts prototype tables for its planet and recipe arguments, restricts a recipe to a single planet only while it is exclusive to that planet, removes the restriction when the recipe becomes shared, and preserves lock_silo = false instead of coercing it to true.
    - Rocket silos now respect a planet's lock_silo = false setting instead of falling back to the default lock.
    - PlanetsLib.assign_entity_replacement() now handles planet lists correctly, including {name = ...} entries, and keeps the supplied name_suffix when expanding a list.
    - PlanetsLib.get_replacement() now finds replacements by the original entity's unit number as documented; both the old and new unit numbers are recorded.
    - Entity replacement now transfers health, crafting progress, bonus progress, direction, turret orientation, loader type, recipe lock, custom status, and proxy/link fields. Fields that are read-only for a particular entity type are skipped instead of aborting the replacement.
    - Entity replacement no longer inserts modules into the new entity a second time after moving the module inventory, so modules cannot be duplicated in the crafting output.
    - Generated entity variants now inherit the base entity's fast_replaceable_group (or its name when no group is set), so the engine accepts upgrades and fast replacement between a variant and the original entity, including locomotives.
    - Rolling-stock replacement now falls back to recreating the rolling stock and restoring its inventories, grid and train state when the engine refuses the in-place upgrade. This also fixes ghost rolling stock, an undefined variable when spilling items, read-only fields, and a leaked global.
    - Replacing an entity whose grid contains equipment ghosts no longer raises "Equipment is not equipment-ghost" when notifying the new entity as script-built.
    - Vehicle ghosts now keep their orientation when an entity replacement rule swaps the ghost, instead of being recreated facing north.
    - The more-than-12-science-pack lab pass now updates an existing lab_input entry in icons_positioning instead of adding a duplicate entry.
    - icon-entry.detect_type() now applies the documented surface > tool > capsule > fluid > planet > item precedence instead of always preferring items.
    - rro.deep_gsub() now writes string replacements back to the list and forwards the gsub flag through recursive deep_replace() calls.
    - Building the returned-ingredient tooltip no longer crashes data-final-fixes when a returned ingredient has no probability; the tooltip uses the amount-only form in that case.
    - Banning a player from a script or the server console no longer errors when by_player is absent; the message reports "server" instead.
    - process_technology_recipe_productivity_effects() now clears the correctly spelled PlanetsLib_recipe_productivity_effects input field, preventing effects from being duplicated on a second call.
    - Pipette-result processing now handles both array and dictionary shapes of defines.prototypes.entity, so custom PlanetsLib_pipette_result values are always registered.
